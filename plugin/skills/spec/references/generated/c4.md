## C4Model

The C4 model a corpus declares, as `specs c4` emits it.

A projection of the index, not a second source of truth: every element is
one the index already holds as a blueprint or a record block, and every
relationship is a `Rel` statement read from a C4 diagram in the document
that owns it. Nothing here is authored by hand.

Elements form a tree, because C4 gives each one exactly one parent: a
system holds containers, a container holds components. Modules are the
exception — a module may be composed into several containers — so they
sit in their own collection and each host lists them by slug.
Relationships are one flat collection for the reason ADR-018 gives for
references: an edge belongs to neither endpoint.

Every relationship in the model is held at the end the corpus declares
it, and the model derives the other end: a container lists its modules
and each module's `contained_by` is derived from those lists; a contract
names its provider and each element's `contracts_provided` is derived
from those names.

| Property | Type | Documentation |
|----------|------|---------------|
| schema_version | String ~= `/^0\.1$/` | The version of this shape. Pinned to one value so a consumer can refuse an artifact it does not understand. |
| workspace | String | The workspace the model was emitted from, as configured in `specs.toml`. Models from several repositories are told apart by it. |
| software_systems | Array<[C4System](#c4system)> | Systems documented by a system blueprint, each holding the containers that declare it.<br><br>Every collection of elements in this model is ordered by slug, and every collection of slugs likewise, so that an unchanged corpus emits byte-identical output. |
| orphaned_containers | Array<[C4Container](#c4container)> | Containers whose blueprint declares no `system`. An orphaned container is a documented fact rather than an omission: a repository may document containers before it documents the system they belong to. |
| orphaned_components | Array<[C4Component](#c4component)> | Components that no container or module declares in its roster — a component blueprint with no parent. C4 gives every component a parent, so an orphaned component is a gap in the corpus. |
| modules | Array<[C4Module](#c4module)> | Every module, once, whatever the number of its hosts. |
| relationships | Array<[C4Relationship](#c4relationship)> | Every dependency edge between two elements, ordered by source slug, then target slug, then description. |
| excluded_relationships | Array<[C4ExcludedRelationship](#c4excludedrelationship)> | `Rel` statements the model does not admit, recorded rather than dropped so that their absence from `relationships` is visible. Ordered by path, then by span. |

## C4Relationship

A dependency edge: the source depends on the target, per the C4
standard's arrow rule.

One relationship may have been drawn in several diagrams — a parent's
internal view and a child's context view show the same edge — and is
recorded once with every drawing listed. Two drawings are the same
relationship when source, target and description agree. Where they
disagree on anything else, the relationship carries the values of the
drawing that sorts first by path and then by span, and the
`c4/drawing-conflict` rule reports the disagreement.

| Property | Type | Documentation |
|----------|------|---------------|
| source | [Citation](vocabulary.md#citation) | Slug of the element that depends. |
| target | [Citation](vocabulary.md#citation) | Slug of the element depended on. |
| level | [C4Level](#c4level) |  |
| description | String | The statement's label, which reads as a sentence between the two names: "Command Surface invokes indexing, checks and queries". |
| technology | String? | The statement's technology argument. |
| detail | String? | The statement's description argument — longer text, never drawn. |
| interaction | [C4Interaction](#c4interaction)? |  |
| contract | [C4ContractLink](#c4contractlink)? |  |
| tags | Array<String>? | Tags in the order written, with the reserved ones removed. |
| drawn_in | Array<[C4Drawing](#c4drawing)> | Every place this relationship was drawn, in document order. |


## C4ExclusionReason

Why a `Rel` statement was excluded from the model.

**Value Type:** String

| Name | Value | Documentation |
|------|-------|---------------|
| external_endpoint | "external_endpoint" | An endpoint is a `Person` or an `_Ext` node. |
| passive_store | "passive_store" | An endpoint is a `Db` or `Queue` node naming no element in scope: a data store the drawing element uses, which the C4 standard gives no blueprint of its own. |
| undeclared_node | "undeclared_node" | An endpoint's label matches no element in scope. |
| ambiguous_node | "ambiguous_node" | An endpoint's label matches more than one element in scope. |
