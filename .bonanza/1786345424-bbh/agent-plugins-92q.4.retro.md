The Definition of Ready has eight checks and **none of them requires a work
order's decisions to be closed.** The gap is not an oversight in the list — the
standard actively permits an open decision:

`plugin/skills/spec/references/work-order-definition-of-ready.md:70-74`
(check 3, `## Design` present):

> Anything past a one-liner needs a Design: the chosen approach and the
> decisions that would otherwise get re-litigated by a time-pressured agent.
> It's mutable and **may hedge** ("leaning toward X because Y; fall back to Z
> if the API can't do it").

"Leaning toward X; fall back to Z" is an open decision, sanctioned by the
standard. `grep -in "decision" work-order-definition-of-ready.md` returns
exactly that one line — there is no other mention in the document.

Downstream, `bead-bonanza` compensates for the gap with an entire phase.
`SKILL.md` Phase 2 (`:266-361`, 96 lines / 4,280 bytes) re-reads every bead,
classifies its decision state as `explicit`/`implicit`/`none`, writes a
decisions document, batch-asks the user, and bakes the answers back into bead
descriptions — mid-sprint, after the readiness gate has already declared the
queue ready. That is backlog refinement happening inside the sprint.

A run is a sprint; grooming is refinement. Decisions belong to refinement. The
readiness gate should be able to state flatly that a groomed bead carries no
open decision, and today it cannot, because the standard it enforces says the
opposite.

This bead closes the standard's gap. The sibling bead deletes the phase that
exists to compensate for it, and cannot land first: deleting Phase 2 while the
DoR still sanctions hedged Designs would remove the safety net and leave the
hole it was covering.

Ownership: the `spec` skill owns this standard. `bead-bonanza` and
`groom-beads` carry generated copies under `references/shared/`, regenerated by
`scripts/sync-shared-references.sh` — the copies must never be hand-edited.


## Retro — implementation

### Findings
- The standard was not the only place sanctioning a hedge. `plugin/skills/spec/references/work-order-template.md:160` carries the same permission as a normative MAY ("It MAY hedge (\"leaning X because Y; fall back to Z...\")") in the `## Design` authoring comment, and it is vendored into two more skills. The bead's Design enumerated the files to touch and did not include it; landing check 9 without it would ship a template that instructs authors to write exactly what the gate now bounces.
- The bead's own worked Example 1 hedged: its Design read "Leaning on golang-jwt/jwt v5". The standard would have failed its own example. Rewritten to state the choice and the rejected alternative.
- groom-beads' checklist at SKILL.md:121 is a phase list (0-7), not an enumeration of the DoR's checks as the Design describes it. Its items are cross-referenced by number elsewhere in the file ("phase 6", "phase 4", "phase 2"), so a new numbered item cannot be inserted without breaking those references.
- Landing this bead's first draft pushed `plugin/skills/groom-beads/SKILL.md` from 19,554 to 20,195 body bytes, tripping the byte gate that the immediately-preceding sibling bead (agent-plugins-92q.2) installed. Two beads in one batch, the second's normal-size prose addition made red by the first's new threshold. The additions were compressed to ~275 bytes; the file now sits at 19,828, only 172 bytes under.

### What I tried that did not work
- First draft added a five-line "An open decision is a bounce, not a guess" paragraph to groom-beads' bounce section plus a two-line checklist sub-item. Correct content, but it is what tripped the byte gate. Replaced by folding the same rule into the existing `blocked-needs-info` bullet as a clause.

### What I decided silently
- The checklist gets a sub-item `2a` rather than a new top-level `9`, to keep the 0-7 phase numbering that the rest of the file cites intact.
- Check 9's title is "No open decisions" (the Contents line and the section heading match), and it is placed after check 8 rather than beside check 3, so the existing eight keep their numbers.
- The template's fix mirrors the standard's wording rather than pointing at it: the comment is read while authoring, when the standard is not open.
- Frontmatter `updated_at` was moved to 2026-08-10 along with the version bump; the bead only named the version.

### Observed pre-fix failure
Not a defect bead. The pre-change state is quoted in the bead's Description: `work-order-definition-of-ready.md:70-74` sanctioned the hedge outright, and `grep -in decision` over the document returned that one line and nothing else.
