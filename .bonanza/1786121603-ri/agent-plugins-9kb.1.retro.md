# agent-plugins-9kb.1 — Declare the reference, finding and registration models in Strata

**Blueprint:** specs/features/reference-integrity/reference-integrity-blueprint.md
— delta **MODEL**, section "Reference, finding and registration models in
Strata (added) — MODEL".
**FRD:** specs/features/reference-integrity/reference-integrity-frd.md.
**Delivery:** staged (stage 1 of 2); this feature's closure set is
`bd list --label feature-spec-reference-integrity`.

Three generated models have to grow before any Go code in this feature can be
written, and all three are declared in Strata and regenerated by one script per
[[adr-016]] — so they change at their source, in one block, rather than being
edited into the generated output. The index gains somewhere to put a reference,
the finding model gains variants for the defects this feature reports, and the
profile registration model gains the two lifecycle facts Document Core cannot
know without being told.

**Regeneration is the whole risk in this block.** This item was blocked on
agent-plugins-j7f: `scripts/generate-schemas.sh` had no strata version floor, and
run with an older binary it regenerated the bundled schema with every inherited
envelope property dropped while reporting success. Committing a destroyed schema
would silently disable the frontmatter checks CI depends on. j7f is closed
(69098fe) and the script now carries a post-generation sanity assertion.

**Verification timing.** This item proves no acceptance criterion on its own. It
participates in AC-SPECREF-001.1, -001.3, -001.5, -001.7, -003.3 and -004.1, each
of which is proved by a later item (REX, RES, XPT, CMD).

**Coordination — agent-plugins-a7m** (out of scope, not fixed here):
`generate-schemas.sh` wipes `cli/core/specmodel`, so a test placed beside the
generated models is destroyed on the next run. Tests for the reference model
therefore live in the consuming packages, as they already do.

**Coordination — agent-plugins-h6c** (out of scope, not fixed here): promoting
the index to a contract document with a formal versioning policy still waits on a
second, independently-built consumer. [[adr-018]] settles the reference shape
only, and the additive-under-1.0 rule this item obeys is what makes shipping
before then safe.

**Supersedes agent-plugins-dgn** — "model references as a separate edge
collection, not only object properties". [[adr-018]] takes exactly that decision
and this item implements it. dgn is left open; the epic's Definition-of-Done item
(agent-plugins-9kb.10) owns closing it.

## Retro

### Approach taken

1. Read the bead, the blueprint's MODEL delta, the whole FRD, ADR-018, the three
   `.strata` sources and the fold target (`module-document-core.md`).
2. Probed the strata compiler on PATH with a scratch schema
   (`/tmp/.../scratchpad/emptystruct`) to confirm that a **field-less struct** is
   accepted as a union variant and generates clean Go and JSON Schema. It is —
   this is what made a discriminated `ReferenceOrigin` / `ReferenceResolution`
   possible rather than a flat enum plus a bag of optional siblings.
3. Wrote the three source deltas, regenerated, reviewed the whole regeneration
   diff, then made the minimal emitter-side updates the new required property
   forced.
4. Folded `module-document-core.md`.

### Model shape as landed

`schemas/index.strata` (all new declarations placed between `IndexExclusion` and
`SpecIndex`, keeping the file's existing dependency order):

- `ReferenceBodyOrigin` (empty) / `ReferenceFrontmatterOrigin { property }`, and
  `@discriminator("kind") union ReferenceOrigin { body, frontmatter-property }`.
- `ReferenceResolved { target_path }` / `ReferenceUnresolved` (empty) /
  `ReferenceNonMember { path, reason?, parse_error? }`, and
  `@discriminator("state") union ReferenceResolution { resolved, unresolved,
  non-member }`.
- `Reference { path, text, slug, anchor?, origin, position, resolution }`.
- `SpecIndex.references: [Reference]` — **required**, like `entries` and
  `exclusions`.

`schemas/finding.strata`: `FindingUnresolvedReference { slug, origin,
non_member? }`, `FindingRetiredTarget { slug, successor? }`,
`FindingIncompletePairing { property, counterpart, source_path, target_path }`,
`FindingReferenceType { property, slug, expected_type, actual_type }`, plus four
variants appended to the `FindingDetail` union with tags `unresolved-reference`,
`retired-target`, `incomplete-pairing`, `reference-type`.

`schemas/profile.strata`: `live_statuses: [Status]?`, `retired_statuses:
[Status]?`, `successor_property: String?` on `ProfileRegistration`, placed after
`placeholder_patterns` and before `conventions`.

### Implicit decisions and why

1. **`references` is required on `SpecIndex`, not optional.** `entries` and
   `exclusions` are required lists, and the model already carries a test
   (`TestNewEmitsEmptyCollectionsRatherThanNull`) whose whole point is that a
   collection consumers iterate must never be `null`. An optional `references`
   would have cost zero Go changes but reintroduced exactly the absent-vs-empty
   ambiguity that test exists to prevent. Cost: `specindex.New` now seeds
   `References: []specmodel.Reference{}`, `corpus.fromIndex` gained the matching
   nil-guard, one golden string and one shape assertion in `specindex_test.go`
   moved, and the three `index-*` snapshot manifests gained `"references": []`.
   Safe on the warm path: `openWarm` reports no errors and rebuilds on any decode
   failure, so a stale `specs.json` written before this change rebuilds rather
   than erroring.
2. **Origin and resolution are discriminated unions over (sometimes empty)
   structs, not enums with optional siblings.** The blueprint says a reference
   "carries" a property name only in the frontmatter case and an exclusion reason
   only in the non-member case; a union makes the unrepresentable states
   unrepresentable, and it matches the `FindingDetail` pattern already in the
   package. Verified empty structs compile and generate correctly before
   committing to it.
3. **Discriminator names: `"kind"` for `ReferenceOrigin`, `"state"` for
   `ReferenceResolution`.** `kind` matches the existing `FindingDetail`
   convention; `state` reads correctly for a resolution outcome and the two
   unions never share an object, so there is no collision.
4. **`Reference.slug` is `String`, not the constrained `Slug` alias.** A
   reference is hand-written and may name something that is not a well-formed
   slug; constraining it would make the very reference that must be reported
   unrepresentable in the index. Recorded in the property's doc comment.
5. **`FindingIncompletePairing` names both ends explicitly (`source_path` /
   `target_path`) rather than following `FindingDuplicateSlug`'s `other_path`.**
   The finding is emitted against *both* documents (AC-SPECREF-002.5) and the two
   copies must describe the relationship in the same direction; `other_path`
   would invert between them.
6. **`FindingReferenceType` carries `slug` in addition to the three facts the
   blueprint names.** AC-SPECREF-002.10's own example message names the target
   ("target 'adr-009' declares type 'adr'"), and the blueprint's stated intent is
   that each variant is self-contained without reopening a document. Additive, so
   no later item is constrained by it.
7. **New union variants appended at the end of `FindingDetail`** rather than
   interleaved by topic, keeping the change purely additive and the generated
   diff minimal.
8. **No wikilinks in `.strata` doc comments.** Existing doc comments name
   documents in prose ("See the Document Relationship Standard"), and the
   generated markdown ships in the plugin rather than the corpus, so a `[[…]]`
   there would be a reference nothing resolves. Followed the existing convention.
9. **Fold scope held to `module-document-core.md`.** The bead's `c4_docs` also
   names `module-spec-profile.md`, but the AC list names only Document Core, and
   the profile-interface widening (and therefore that document's fold) is
   agent-plugins-9kb.2 (XPT). ADR-018's Context sentence "today it carries
   `entries` and `exclusions`" was left alone: an ADR Context describes the state
   at decision time.

### Differences from the dispatch instructions

- The instructions describe this as a Strata-sources-only change. Making
  `references` a required property forced six small non-generated edits
  (constructor, warm-path nil guard, two test expectations, three snapshot
  manifests). Judged in-scope: without them the tree does not compile clean and
  `go test ./...` cannot pass. No test was added anywhere, and nothing was placed
  in `cli/core/specmodel`.

### Surprises

- The three `index-*` snapshot manifests' `input_hash` values changed even though
  no fixture document did. `Fingerprint` folds the active profile's schema into
  the hash, and the profile's schema is the regenerated bundle — so a model change
  correctly invalidates every warm index. Expected behaviour, but not obvious
  from the failure output, which reads as a corrupted fixture.
- `strata` accepts a field-less struct and emits `{"additionalProperties": false,
  "properties": {}}` plus a bare Go `struct{}` that satisfies the union
  interface. Nothing in the vendored language reference states this either way;
  it was established by probe.
