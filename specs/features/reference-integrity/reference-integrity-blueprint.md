# Spec corpus reference integrity

## Overview

**FRD:** [[frd-spec-reference-integrity]]

[[module-document-core]] already declares a References component and
records that it isn't built. There's no `cli/core/references` package, the
module has no markdown-parsing dependency, and the index carries no
reference data, so no check reports a `[[slug]]` that names no document.
This feature builds the component.

Reference extraction runs inside the corpus walk that already reads every
candidate's bytes. Resolution runs against the slugs the index already
holds. The resulting graph is persisted as a new edge collection on
`SpecIndex`, the shape [[adr-018]] decides. That collection is the one
thing this feature adds to the index's schema.

Everything domain-specific about a reference arrives through the profile
extension point: which frontmatter properties hold one, which must resolve
to a particular document type, and which statuses mean a document is live
or retired. This feature widens that extension point for the first time
since it was defined.

Nothing here reads a heading or writes a document. Headings belong to
[[frd-spec-structure-conformance]], and writing documents belongs to
[[frd-spec-slug-rename]]. The anchor half of a reference belongs to
[[frd-spec-anchor-references]]. This feature splits a reference on its
first `#` and resolves only the slug half.

The delta blocks, in dependency order, are:

1. MODEL: reference edges, finding variants, and lifecycle registration in
   Strata.
2. XPT: the widened `Profile` extension point.
3. REX: reference extraction.
4. RES: resolution and the graph.
5. PREG: this framework's profile registrations.
6. CHK: reference integrity checks.
7. LIFE: lifecycle and relational checks.
8. CMD: the `refs` subcommand and rule registration.

## Element deltas

### Reference, finding and registration models in Strata (added) — MODEL

**Intent:** Three generated models have to grow before any Go code in
this feature can be written. Per [[adr-016]], all three are declared in
Strata and regenerated by one script. So they change at their source, in
one block, instead of being edited into the generated output. The index
gains a place to put a reference. The finding model gains variants for the
defects this feature reports. The profile registration model gains the two
lifecycle facts that Document Core can't know unless it's told.

**Data (Strata sources, `schemas/`):**

- `index.strata` gains a `Reference` struct and a top-level `references`
  list on `SpecIndex`, per [[adr-018]]. A `Reference` carries:
  - the `path` of the document the reference occurs in;
  - the reference `text` as written, and the `slug` half of it;
  - the `anchor` half, uninterpreted and absent where the reference
    names none (AC-SPECREF-002.2);
  - the `origin`, distinguishing a reference parsed from the body from
    one held by a named frontmatter property and carrying that property
    name (AC-SPECREF-001.7);
  - the `position`, as the existing `Span`;
  - the `resolution`: resolved, naming the target's path; unresolved; or
    matched-a-non-member, carrying the exclusion reason or the parse
    failure (AC-SPECREF-002.7).
- Behavior: `schema_version` SHALL remain `"1.0"`. The new list is an
  addition alongside the existing shape, and [[container-spec-cli]]'s
  additive rule permits an addition at the same version. The model and the
  emitted index change together in one change, which satisfies
  [[module-document-core]]'s lockstep rule on the index model.
- Behavior: `references` SHALL be a list whose order the emitter fixes,
  so AC-SPECREF-001.5's document-order requirement and AC-SPEC-009.7's
  byte-identical output are properties of how the emitter fills one
  list rather than of a directory walk.
- `finding.strata` gains `FindingDetail` variants, each carrying enough
  to make its finding self-contained without reopening a document:
  - an unresolved reference, carrying the slug and the origin, plus the
    reason and the file's path where the slug matched a file the index
    recorded as excluded or unparsable (AC-SPECREF-002.1,
    AC-SPECREF-002.3, AC-SPECREF-002.7);
  - a retired target, carrying the target's slug and its successor value
    where it declares one (AC-SPECREF-002.6);
  - an incomplete pairing, carrying both property names and both
    documents (AC-SPECREF-002.5);
  - a reference-type mismatch, carrying the property, the expected
    `type`, and the `type` the target declares (AC-SPECREF-002.10).
- `profile.strata` gains these fields on `ProfileRegistration`:
  `live_statuses` and `retired_statuses`, each a list of `Status`, and
  `successor_property`, the name of the property in which a retired
  document names its replacement. These fields are profile-level, not
  per-type, because `status` and `superseded_by` are envelope properties.
  `DocumentTypeRegistration` already carries `reference_properties`,
  `typed_reference_properties`, and `pairings`. This feature is their
  first consumer and adds nothing to them (AC-SPECREF-004.1).

**Anchors:** `schemas/index.strata`, `schemas/finding.strata`,
`schemas/profile.strata`; `scripts/generate-schemas.sh`, which regenerates
`cli/core/specmodel/`, `cli/core/schema/`, and the plugin markdown.
Regeneration is the whole risk in this block. The strata version floor
prerequisite in Tracker reconciliation must land first.

### Profile extension point in [[module-document-core]] (modified) — XPT

**Intent:** Every fact this feature checks is vocabulary, and Document
Core must not hold any of it. Since it was defined, the `Profile`
interface has carried three members: a union schema, a per-type slug and
numbered table, and the convention defaults. Its own documentation names
reference properties and lifecycle rules as the capabilities that would
widen it. This delta is that widening. It's reviewed on its own merits, as
[[module-spec-profile]]'s Change guidance requires, and it's framed so
that any profile can express these rules, not only this one.

**Behavior:**

- `DocumentTypeRules` SHALL carry, per document type, the names of its
  reference-bearing frontmatter properties, its typed reference
  properties as a mapping from property name to the `type` its target
  must declare, and its property pairings (AC-SPECREF-004.1).
- The `Profile` interface SHALL additionally supply the lifecycle
  registration: the statuses at which a document is live, the statuses
  at which it is retired, and the name of the property in which a
  retired document names its replacement.
- Document Core SHALL NOT contain the literal `retired`,
  `superseded_by`, or any registered property name. The existing
  boundary test — no non-test source in `cli/core/corpus` carries a
  document-type literal — SHALL extend to the values this delta
  registers, so the widening cannot become a place to smuggle
  vocabulary into the host.
- WHEN a profile is activated, the module SHALL validate its
  registration (AC-SPECREF-004.3). The defects are:
  - a pairing or a typed reference naming a property that the same type
    doesn't register as reference-bearing;
  - a typed reference naming a `type` the profile doesn't define;
  - a lifecycle registration naming a status outside the profile's own
    vocabulary.
- IF the registration carries a defect, THEN the module SHALL report
  every one it finds, naming the offending key, rather than falling back
  to a default for that key.
- The validation SHALL return its defects to the caller rather than
  rendering them, because a compiled-in registration has no file
  position of its own. The command surface supplies the position (CMD).

**Anchors:** `cli/core/corpus/profile.go` (`Profile`,
`DocumentTypeRules`); the boundary tests in `cli/core/corpus`; the
generated `specmodel.DocumentTypeRegistration` and
`specmodel.ProfileRegistration` that MODEL extends.

### References in [[module-document-core]] (added — extraction) — REX

**Intent:** Build the extraction half of the module's declared References
component. The component finds every reference a document makes, in the
body and in the frontmatter properties the active profile registers. It
records each one with the position a reader must open to fix it. The two
rules that matter most here say what isn't a reference: a backticked
illustration, and a frontmatter value that describes the notation. A
checker that reports either one gets ignored.

**Behavior:**

- The component SHALL parse every `[[…]]` occurrence from a document's
  body — the content after the frontmatter block — and record each with
  its `Span` (AC-SPECREF-001.1).
- The component SHALL NOT record an occurrence inside a fenced code
  block or an inline code span (AC-SPECREF-001.2). Code regions SHALL
  be located with `goldmark`, the markdown parser [[adr-015]] already
  chose for this module, rather than by a hand-rolled backtick scan:
  where a code span ends depends on matching backtick-run lengths, fence
  lengths and info strings, and a hand-rolled masker getting one of those
  wrong produces exactly the false positive this criterion exists to
  prevent. This brings `goldmark` into the module ahead of the Markdown
  Structure component, which [[module-document-core]] currently says it
  arrives with. Nothing here builds that component or reads a heading.
- The component SHALL treat everything before the first `#` as the
  reference's slug half and everything after it as the anchor, which it
  records and does not interpret (AC-SPECREF-002.2). No other separator
  is interpreted. `cross-document-references.md` forbids the display
  alias `[[slug|text]]`, so such a reference carries `slug|text` as its
  slug half. It reports as unresolved instead of quietly resolving to
  something the standard prohibits.
- The component SHALL read reference-bearing frontmatter properties
  from the generic parsed frontmatter — the property tree the
  Frontmatter component retains with raw text and positions — and never
  from the typed `DocumentFrontmatter` envelope, which carries neither
  per-type properties nor positions
  (AC-SPECREF-001.7).
- WHERE a reference-bearing property holds a sequence, the component
  SHALL record one reference per item, each at that item's own span.
  This widens the Frontmatter component, whose `Property` today carries
  the span of a whole value. AC-SPECREF-002.3's finding and
  AC-SPECREN-001.4's rewrite both need the item, not the list.
- The component SHALL NOT record a `[[…]]` occurring in a frontmatter
  value as a reference (AC-SPECREF-001.4).
- The component SHALL read the contents of an HTML comment block as
  body text. AC-SPECREF-001.2 excludes only code.
  `template-authoring-standards.md` requires a finished document's
  comment blocks to be deleted, so masking them would hide a reference in
  a document that shouldn't carry the block at all.
- The component SHALL record each occurrence separately and preserve
  source order, so a document referencing the same target twice carries
  two references with two spans (AC-SPECREF-001.5).
- The component SHALL express every position it reports as a `Span`
  from the Spans component. That's how a delta that adds a parser
  satisfies [[module-document-core]]'s rule to "build a new parsing
  capability on the Spans delimiter scanner." Positions are still
  computed one way, and `goldmark` supplies the region mask that the
  scanner can't derive correctly.

**Anchors:** new package `cli/core/references` (the package
[[module-document-core]]'s References component names);
`cli/core/frontmatter` for the per-item span widening; `cli/core/span`;
`goldmark` added to `cli/go.mod`.

### References in [[module-document-core]] (added — resolved graph) — RES

**Intent:** Turn extracted references into a resolved graph and put it in
the index. Resolution is a lookup against slugs the corpus already holds,
so this delta adds no second pass. Its cost is the walk it already rides
on. The graph lets a single-document check see the documents that point
at the document being checked, and it's what the `refs` query reads.

**Behavior:**

- The component SHALL resolve a reference's slug half against the slugs
  corpus members declare, compared lowercased, matching the
  case-insensitive slug uniqueness AC-SPEC-003.4 establishes
  (AC-SPECREF-002.8).
- WHEN a reference's slug matches a file the index recorded as an
  exclusion, or an entry recording a parse failure, the component SHALL
  record that outcome rather than "matches nothing", carrying the reason
  and the file's path (AC-SPECREF-002.7).
- The component SHALL resolve only within the workspace the run is
  against. A slug declared only in another repository's index is
  unresolved, per the FRD's stated boundary.
- The component SHALL derive inbound references from the same
  collection the outbound ones are read from ([[adr-018]],
  AC-SPECREF-001.3).
- The component SHALL NOT store the reverse of an edge a second time.
- WHEN a reference resolves to no corpus member, the component SHALL
  record it in the index with its unresolved state, so `index` exits
  zero over a corpus whose links are broken (AC-SPECREF-001.6).
- Corpus SHALL extract and resolve during the walk that already reads
  each candidate's bytes, so that no document is read twice.
- WHERE a corpus is served warm, Corpus SHALL read the graph from the
  persisted index rather than parsing any document — which is what
  keeps the `refs` query and the inbound half of a single-document
  check inside the AC-SPEC-009.1 and AC-SPEC-009.2 budgets
  (AC-SPECREF-003.4).
- Corpus SHALL expose lookups for both directions alongside the
  existing `Entry` and `Slug`, built once when the index is opened.

**Anchors:** `cli/core/references`; `cli/core/corpus/corpus.go`
(`Build`, the `builder`, and the `Corpus` lookups); the emitted index
`corpus.Write` produces and `corpus.Open` serves. Its `input_hash` already
folds in the active profile's registration, so a profile that registers a
new reference property invalidates the warm index by construction.

### specs registrations in [[module-spec-profile]] (modified) — PREG

**Intent:** Supply this framework's own answer to everything XPT asks a
profile for, so an adopting repository gets reference integrity without
authoring a profile (AC-SPECREF-004.2). This delta is data, not code, as
[[module-spec-profile]]'s own guarantee to "register it as data rather
than implement it as code" asks. That's also why the module's planned
Lifecycle Rules component turns out to need no package of its own.

**Behavior (written in [[module-spec-profile]] vocabulary):**

- The profile SHALL register as reference-bearing every frontmatter
  property in `schemas/frontmatter.strata` that holds a document slug:
  `superseded_by` on every type; `sources` on FRDs; `frd` on
  feature blueprints; `system` on container blueprints; `contained_by`
  on modules and components; `contracts_provided` and
  `contracts_consumed` on the four blueprint types that inherit
  `ContractEdges`; and `provider` and `consumers` on contracts.
  - This set departs from the FRD's example on purpose. AC-SPECREF-004.2
    illustrates the set without `provider` and `consumers`. Both hold
    slugs by declaration, and both resolve today in this corpus. Omitting
    them would leave a contract's two most load-bearing edges unchecked.
    The criterion covers "this framework's own reference-bearing
    properties," and its example is illustrative. This list is the
    complete set.
- The profile SHALL register no pairing. Every relationship this
  framework declares has its reverse derived from inbound edges, and
  [[document-relationship-standards]] reserves a pairing for the case
  that doesn't arise here. So the pairing check is inert for this corpus
  by design. That's a property to assert, not an omission to explain.
- The profile SHALL register exactly one typed reference: a feature
  blueprint's `frd` must resolve to a document of `type: frd`
  (AC-SPECREF-002.10).
- The profile SHALL register `retired` as its only retired status,
  every other status in its vocabulary as live, and `superseded_by` as
  the successor property. Every status other than `retired` is live
  because the retired-target warning exists to tell an author what to
  cite instead. The author most likely to need that is editing a draft.
  The successor property is registered so the warning can quote the
  replacement (AC-SPECREF-002.6). Nothing requires a retired document to
  declare one.
- The registered set SHALL be derived from `schemas/frontmatter.strata`
  rather than transcribed from it by hand.
- A test SHALL assert that every property typed `Slug` or `[Slug]` in
  the generated vocabulary is registered by the type that declares it —
  the same drift guard the existing per-type table already carries for
  document types.

**Anchors:** `cli/profile/profile.go` (the `documentTypes` table and the
`New` constructor); `cli/profile/profile_test.go` (the
vocabulary-coverage test this delta extends);
`cli/profile/self_application_test.go`, the gate that runs this profile
over this repository's own `specs/` corpus. That gate proves the
registrations against real documents.

**Reconciliation for retirement:** [[module-spec-profile]]'s Lifecycle
Rules component is declared as a Go package whose "relational part needs
code." With the registration surface XPT defines, it needs no code. The
statuses, the successor property, and the pairings are data, and the
checks that read them live in Document Core (LIFE). The component becomes
a registration instead of a package. Element Records stays untouched and
unbuilt.

### Reference integrity checks in [[module-document-core]] (added) — CHK

**Intent:** Report the reference that resolves to nothing. The whole
feature exists for this check. Its severity is fixed here because a
build's exit status depends on it.

**Behavior:**

- WHEN a document body contains a reference whose slug matches no corpus
  member, the check SHALL report a finding of severity `error` under the
  rule identifier `reference/unresolved`, carrying the file, the span
  and the unresolved slug (AC-SPECREF-002.1).
- WHEN a value in a reference-bearing frontmatter property matches no
  corpus member, the check SHALL report the same rule at `error`, with a
  detail naming the property and the value (AC-SPECREF-002.3).
- WHEN a reference's slug matched an excluded file, the check SHALL
  report the same rule with the non-member detail rather than as a slug
  matching nothing; WHEN it matched a parse failure, the check SHALL
  report nothing against the referrer, the parse failure being the one
  finding (AC-SPECREF-002.7, as amended for AC-SPEC-003.8).
- WHEN a single document is checked, the check SHALL report every
  reference finding located in the document named, and of those located
  elsewhere only the `reference/unresolved` findings of references
  citing a slug the document declared at git HEAD and no longer
  declares, and the `reference/unresolved-anchor` findings of references
  resolving to it — each against the referring document at the
  referrer's own span (AC-SPECREF-002.9, AC-SPECREF-002.11). The
  document that breaks a reference is never the document that holds it.
  These findings are the ones the author's edit caused, and an unrelated
  broken reference elsewhere isn't one of them. Beyond the corpus-wide
  check that already runs, this costs one `git` read of the document at
  HEAD. Either way, the findings come from the reference collection held
  in memory, so AC-SPEC-009.2's single-document budget is untouched.
- WHEN a single document is checked outside a git work tree, or where
  git cannot be run, the check SHALL note on standard error that the
  references elsewhere were not checked and report the document's own
  findings (AC-SPECREF-002.13).
- WHEN a single document is checked and the path names no corpus member,
  the check SHALL report that rather than a report with no findings. A
  report that selects nothing and renders every rule as `passed` looks
  the same as a report on a document that conformed. That's the vacuous
  pass that AC-SPECREF-004.3's rationale exists to prevent, arriving by a
  different route. A candidate the index recorded as excluded SHALL
  report the reason the index already holds; a path discovery never saw
  SHALL report that instead.
- The check SHALL declare `reference/unresolved` to the run report so
  that `--only` can name it and a run distinguishes it having passed
  from its not having been requested (AC-SPEC-006.8, AC-SPEC-006.9).

**Anchors:** `cli/core/corpus/check.go` (where `Check` and `CheckFor`
already fold per-member validation into one report);
`cli/core/finding/finding.go` (the rule constant and the constructors
for the MODEL variants); snapshot cases under `cli/testdata/cases/`.

### Lifecycle and relational checks in [[module-document-core]] (added) — LIFE

**Intent:** Cover the half of reference integrity that's about what a
reference means rather than whether it lands. That half is a live
document citing a retired one, a half-declared pairing, and a typed
reference resolving to the wrong kind of document. Each of these depends
entirely on what the active profile registered, so the code is
framework-agnostic and the judgment is the profile's.

Nothing here requires a retired document to have a successor. An earlier
criterion did. It was removed from [[frd-spec-reference-integrity]]
because not every retirement is a replacement. The half worth keeping
survives without the criterion. `superseded_by` is a registered
reference-bearing property (PREG), so a successor that names no corpus
member is already an error under AC-SPECREF-002.3, and CHK reports it.

**Behavior:**

- WHEN a document at a status the profile registers as live references a
  document at a registered retired status, the check SHALL report a
  finding of severity `warning` under `reference/retired-target`, naming
  the retired target and its successor value where it has one
  (AC-SPECREF-002.6). It's the first registered check in this tool to
  emit `warning` at all. That makes AC-SPEC-006.7's `--strict` boundary
  reachable end to end for the first time.
- WHEN the profile registers a pairing and the resolved target does not
  declare the counterpart naming back, the check SHALL report a finding
  of severity `error` under `reference/pairing-incomplete` against both
  documents (AC-SPECREF-002.5). The finding against the declaring
  document is at the declared value's span. The finding against the
  target is at the span of its frontmatter block, because an absent
  property has no position of its own.
- WHEN the profile registers a required target `type` for a
  reference-bearing property and the resolved document declares a
  different `type`, the check SHALL report a finding of severity `error`
  under `reference/type-mismatch`, naming the property, the type
  expected and the type the target declares (AC-SPECREF-002.10).
- WHERE a check's registration is empty — no pairing registered, no
  typed reference — the check SHALL still be requested by a run that
  requests it.
- WHERE such a check is requested, its outcome SHALL be `passed` rather
  than `not-requested`. "The profile registers no pairing" and "the
  pairing check did not run" are different facts, and AC-SPEC-006.9
  exists to keep them apart.

**Anchors:** `cli/core/corpus/check.go`; `cli/core/finding/finding.go`;
snapshot cases under `cli/testdata/cases/`, which need fixture corpora
carrying a retired document and a registered pairing. This repository's
own corpus supplies neither.

### Command Surface in [[container-spec-cli]] (modified) — CMD

**Intent:** Expose the graph as a fifth subcommand, and wire the new rules
into the accounting the command surface already does. This delta extends
the surface that FEAT-SPEC-011 fixed without renaming or repurposing any
of its four subcommands, which is the growth that requirement anticipated.
The command surface holds no domain logic. `refs` converts a slug and a
direction into a corpus lookup, and converts the result into stdout.

**Behavior:**

- The command surface SHALL expose a `refs` subcommand taking one slug,
  returning by default every corpus member whose body or registered
  frontmatter properties reference it (AC-SPECREF-003.1), and returning
  the documents that slug references instead when `--outbound` is given
  (AC-SPECREF-003.2).
- `refs --json` SHALL emit each returned reference with its file path
  and span (AC-SPECREF-003.3).
- `refs` SHALL open the corpus warm and answer within the budget
  AC-SPEC-009.1 sets for a corpus query (AC-SPECREF-003.4).
- WHEN no corpus member references the named slug, `refs` SHALL report
  that and exit zero (AC-SPECREF-003.5).
- WHEN no corpus member declares the named slug at all, `refs` SHALL
  report that distinctly from the case above.
- WHEN the named slug is undeclared, `refs` SHALL exit zero, matching
  the contract `slug-exists` sets in AC-SPEC-007.2.
- `refs` SHALL appear in the subcommand listing with its own flags,
  derived from the same declaration that defines it, per the container's
  Change Guidance (AC-SPEC-011.5).
- The command surface SHALL declare the three new rule identifiers to the
  run report, so `--only` names them and `--strict` reaches the
  `reference/retired-target` warning.
- WHEN activating a profile whose registration the XPT validation
  rejects, the command surface SHALL report each defect as a finding
  naming the offending key, positioned at the `[profile].name` value in
  `specs.toml` — the only file position a compiled-in registration has
  (AC-SPECREF-004.3).
- IF a registration defect is reported, THEN the command surface SHALL
  NOT fall back to a default for the offending key.

**Anchors:** `cli/cmd` (`Execute` and the existing four subcommands,
`Registry` and `Load` for the profile-activation path); snapshot cases
under `cli/testdata/cases/`; `scripts/regenerate-cli-snapshots.sh`.

- [[module-document-core]]'s Findings component: the severity

- `scripts/generate-schemas.sh` and the Strata toolchain: MODEL extends
  its inputs; every later delta relies on its output.

## Contracts

- [[contract-specs-configuration]] (revised, drafted in place): the
  contract's description of the internal registration surface enumerates
  what a profile supplies. It doesn't yet mention reference-bearing
  properties, typed references, pairings, or the lifecycle registration.
  The revision is additive and touches only the internal half. That
  contract's own change policy exempts the internal half from versioning
  while both modules are `visibility: internal`. The public `specs.toml`
  surface is untouched, so no `version` bump is required and no adopting
  repository's file changes meaning.
- No new contract document. The index gains a reference collection, but
  promoting the index to a contract still waits on a second,
  independently built consumer. [[adr-018]] decides the shape, and the
  generated JSON Schema remains its interim machine-readable
  specification. This is a scope decision, not an open question, and it
  doesn't block grooming.

## Tracker reconciliation

- **Prerequisite**: `generate-schemas.sh` has no strata version floor. Run
  with an older binary, it regenerates the bundled schema with every
  inherited envelope property dropped, and it still reports success.
  MODEL regenerates all three Strata sources, so this feature can't start
  until the floor (or the equivalent post-generation assertion) is in
  place. Committing a destroyed schema would silently disable the
  frontmatter checks that CI depends on.
- **Subsumed by MODEL**: "model references as a
  separate edge collection, not only object properties." [[adr-018]]
  takes exactly that decision and MODEL implements it. Grooming blocks
  the issue on the MODEL work order, and the Definition of done closes it
  against the ADR.
- **Subsumed by LIFE**: AC-SPEC-006.7 is declared at `integration` but
  unreachable, because no registered check emits `warning`.
  `reference/retired-target` is the first that does, so a snapshot case
  can reach the `--strict` boundary. The issue is `deferred`, and grooming
  blocks it on the LIFE work order.
- **Out-of-scope**: index entries carry only the `DocumentFrontmatter`
  envelope, so per-type properties are lost. REX reads reference-bearing
  properties from the generic parsed frontmatter, not the typed envelope,
  so this feature neither depends on that issue nor resolves it. The
  boundary: nothing in these deltas may reach a reference-bearing value
  through `IndexEntry.frontmatter`. The envelope carries neither the
  per-type properties nor the spans AC-SPECREF-001.7 requires.
- **Out-of-scope** (deferred follow-up): "ADR: index schema and
  versioning." [[adr-018]] settles only the reference shape. Promoting the
  index to a contract document with a formal versioning policy still
  waits on a consumer that exists. The additive-under-1.0 rule this

- **Out-of-scope** (coordination): `generate-schemas.sh` wipes
  `cli/core/specmodel`, so a test placed beside the generated models is

  do.
- **Resolved** (coordination): the schema is closed
  (`rejectUnknownProperties: true`, strata v0.8.0), so unknown frontmatter
  keys are rejected. These checks read the generic property tree, not the
  validated envelope. Closure flattens each type's inherited properties
  inline, so the registered reference properties remain in the per-type
  definitions.
- **Out-of-scope**: the generated models embed this framework's
  `DocumentType` vocabulary, coupling the framework-agnostic half to it.
  XPT widens the extension point without adding vocabulary to the host,
  and extends the existing boundary test to the new registered values. It
  neither worsens nor fixes that coupling.
- **Out-of-scope** (coordination): `regenerate-cli-snapshots.sh` was a

  feature subsumes.

## Sequencing constraints

- `delivery: staged`. Two stages, each a reviewable increment:
  - Stage 1 (the graph in the index): MODEL, XPT, REX, RES, and PREG.
    `specs index` emits reference edges over this repository's own
    corpus. No new check runs, no finding is raised, and no exit status
    changes. The stage boundary is deliberate. It puts the extraction and
    resolution rules, which are the ones that produce false positives, in
    front of a reviewer before any of them can fail a build.
  - Stage 2 (checks and query): CHK, LIFE, and CMD. The checks report,
    `refs` answers, and exit status becomes sensitive to references for
    the first time.
- The MODEL delta SHALL land before every other delta: all of them
  consume types it generates.
- The XPT delta SHALL land before PREG, which populates the widened
  interface, and before LIFE, which reads it.
- The REX delta SHALL land before RES, which resolves what it extracts.
- The RES delta SHALL land before CHK, LIFE and CMD, all of which read
  the resolved graph.
- The PREG delta SHALL land before LIFE, whose every check is inert
  without a lifecycle registration, and before REX's frontmatter
  extraction can be exercised against this repository's corpus.
- The CHK and LIFE deltas SHALL land before or with CMD, which declares
  their rule identifiers to the run report.
- Lockstep rules that span delta blocks, and how each is satisfied:
  - [[module-document-core]] requires the schema version and the emitted
    index to change together when the index model changes shape. Both
    are in MODEL, and the version is deliberately not bumped. The
    reference collection is an addition under the additive-at-1.0 rule
    that [[container-spec-cli]] states, so the act that satisfies the
    rule is the recorded decision not to bump, not an omission.
  - [[module-document-core]] requires a new parsing capability to be
    built on the Spans delimiter scanner. REX adds `goldmark` for code
    region masking and still reports every position as a `Span`. The
    rule's purpose, one way of computing a position, holds. The narrowing
    folds into the module blueprint at retirement.
  - [[container-spec-cli]] requires the snapshot regeneration script to
    be run and every diff reviewed when observable output changes. CHK,
    LIFE, and CMD each change observable output. Each lands with its
    regenerated snapshots in the same change, not in a shared
    regeneration pass at the end of stage 2.
- No backward-compatibility window applies. [[module-document-core]] and
  [[module-spec-profile]] are both `visibility: internal` and evolve in
  lockstep with their only consumer. The widened extension point is the
  internal half of [[contract-specs-configuration]], which that
  contract's change policy exempts while both modules are internal.

## Key decisions

- [[adr-018]]: references are one top-level edge collection on
  `SpecIndex`, with both directions derived from it. It was authored
  alongside this blueprint, and MODEL and RES apply it.
- [[adr-016]]: Strata is the single source for generated models, which
  is why MODEL is a Strata delta rather than three Go edits.
- [[adr-015]]: Go and `goldmark`. REX brings `goldmark` into the module
  for code-region masking, ahead of the Markdown Structure component that
  the module blueprint currently says it arrives with.
- [[adr-012]]: the `[[slug]]` and heading-anchor conventions REX parses
  and RES resolves, and the anchor convention this feature splits on and
  leaves to [[frd-spec-anchor-references]].
- [[adr-009]]: parents own child edges. [[adr-018]] extends that
  ownership logic from the documents to the index that describes them.

## Open questions

None. One question came up during authoring and is resolved. A criterion
that required every retired document to declare a resolvable successor
reported an `error` against every retired feature blueprint. A feature
blueprint retires when its Definition of done is complete, not because
something replaced it. The criterion was removed from
[[frd-spec-reference-integrity]], and whether retirement should imply a
successor for some document types is left to a future revision. The
half worth keeping needs no criterion of its own. `superseded_by` is a
registered reference-bearing property, so a successor naming no corpus
member is already an error under AC-SPECREF-002.3.
